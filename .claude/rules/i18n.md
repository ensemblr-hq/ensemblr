# Localization Policy

Ensemblr ships in English, Russian, and Greek. A change that adds or edits a
user-facing surface is not finished until all three read it in their own
language.

`src/renderer/AGENTS.md` is normative on *how* a string is authored — `t()` call
sites, `useTranslation()` versus the singleton, memo dependencies, plural
composition. This file is the *completion contract*: when a translation must
exist, what counts as a surface, and how to produce one.

## The Rule

**Every user-facing string your diff adds or touches ships translated into `ru`
and `el` in the same change.** No key your change introduces may be left with an
empty value in `src/renderer/lib/i18n/locales/ru/*.json` or
`src/renderer/lib/i18n/locales/el/*.json`.

Two triggers, not one:

1. **You write a new surface, or a new string on an existing one.** Author it as
   a key and fill all three locales.
2. **You work on a surface that is not translated yet.** A file you are already
   editing comes out clean: migrate its hardcoded literals to keys, and fill any
   empty `ru`/`el` values for the keys on that surface. "The English was already
   there" is not an exemption for a file you are changing anyway.

The second trigger is bounded by the file you touched. You are not required to
clear the repository-wide backlog in an unrelated change — but you may not add
to it.

## What Counts As User-Facing

Translate: visible copy, button and menu labels, dialog titles, placeholders,
tooltips, `aria-label`/`title`/screen-reader-only text, toasts, empty states,
validation and error messages, notification bodies, and any English fallback
that `src/main` or `src/shared` hands the renderer to display.

Leave alone: log lines, diagnostic and support-bundle text, thrown `Error`
messages that never reach a surface, code identifiers, telemetry, test fixtures,
and the vendored primitives under `src/renderer/components/ui/`.

Agent-facing prose is a separate mechanism, not a catalogue: agents are steered
by `buildLanguageDirective` in `src/shared/agent-control/language-directive.ts`,
which names the app's language in the prompt. A new instruction or tool
description stays English there — do not migrate it to `t()`, and do not
hardcode an assumption that the agent will answer in English.

## Workflow

```
npm run i18n:extract   # regenerates locales/en + empty ru/el skeletons from call sites
#   → fill every "" your diff created, in locales/ru and locales/el
npm run i18n:types     # regenerates src/renderer/types/i18next.d.ts
npm run i18n:status    # none of your keys may appear as untranslated
npm run check          # runs i18n:lint
```

`locales/en/**` is **generated** from the `t('key', 'Default English')` call
sites — never hand-edit it; change the default in the call site and re-extract.
`locales/ru/**` and `locales/el/**` are **hand-filled** against that generated
skeleton. They are the one place in the tree where you type translation text.

## Translating

- **Read `docs/i18n-glossary.md` first.** Reuse the term that is already fixed
  there rather than coining a second one; a divergent term is a cross-cutting
  rename after the fact.
- **A term with no glossary row gets one in the same change**, with a note on
  the call you made.
- **Proper nouns and git porcelain stay English** — `Ensemblr`, `Pi`,
  `Claude Code`, `Linear`, `GitHub`, `commit`, `branch`, `merge`, `worktree`,
  `HEAD`.
- **Russian and Greek run 15–30% longer.** Pick the shortest term that survives
  a sidebar or tab-strip column.
- **Fill every plural category.** `i18n:extract` writes the CLDR skeleton per
  locale: `ru` gets `_one`/`_few`/`_many`/`_other`, `el` gets `_one`/`_other`.
  Do not collapse them into one form and do not concatenate a count onto a
  translated noun.
- **Interpolation placeholders survive verbatim.** `{{provider}}` in English is
  `{{provider}}` in Russian and Greek; `i18n:lint` runs
  `checkInterpolationParams` and fails on a renamed or dropped one.
- **Do not guess a term you are unsure of.** Check the glossary, then ask. A
  fluent-sounding wrong noun is harder to find later than an empty string.

## Codes Cross The Process Boundary, Not English

`src/shared/` and `src/main/` cannot reach the renderer's i18n instance, so a
label they return is English forever. They return a locale-neutral code — with
an English fallback for the support bundle — and the renderer translates it.
`src/main/setup/setup-checks-core.ts` pairs `label` with
`labelMessage: { code }`; `src/renderer/lib/setup-check-text/` maps every code
to a `t()` call. Two sibling mappers do the same for their own unions:
`src/renderer/lib/failure-text/` covers every failure code exported from
`src/shared/ipc/contracts/`, so a new code in main is a compile error rather than
English prose on a translated screen, and
`src/renderer/lib/provider-check-text/` covers the provider readiness checks.

**Adding a code in main or shared is therefore a user-facing change.** The
renderer mapper needs the matching `case` with its `t()` call, and that key
needs `ru` and `el` filled — otherwise the union grows and the surface silently
renders the English fallback.

Surfaces the main process draws itself are the exception, because there is no
renderer to hand a code to. Each keeps a const table keyed by language rather
than booting i18next into the main bundle, and a new key fills `en`, `ru`,
**and** `el` in the same change:

- `src/main/menu/menu-strings.ts` — the native macOS menu bar. Thirty static
  labels the renderer never sees.
- `src/main/agent-runtime/notification-strings.ts` — desktop-notification copy.
  The OS notification is posted from main, so there is no renderer to translate
  it; the *title* is the chat tab's own name, which the naming pipeline already
  produces localized, so only the body and the unnamed-tab fallback live here.
- `src/main/app/quit-guard-strings.ts` — the native "agents are still running"
  quit confirmation.
- `src/main/linear/linear-callback-page-strings.ts` — the page the *browser*
  lands on after a Linear OAuth redirect. Served as HTML by the loopback
  callback server, so the reader is a browser tab rather than the renderer and
  there is nothing to hand a code to.
- `src/main/menu/about-panel-strings.ts` — the credit headings on the native
  About panel. The panel is drawn by the OS (GTK on Linux, AppKit on macOS)
  from the options `app.setAboutPanelOptions` is handed, so there is no
  renderer in the loop. The credited package names, licenses, and URLs beneath
  each heading are generated data and stay untranslated.

None is reached by `i18n:extract` or `i18n:lint`, which scan `src/renderer/**`
only, so each carries a parity test asserting the same key set across all three
languages with no empty values (`tests/main/menu-strings.test.ts`,
`tests/main/notification-strings.test.ts`,
`tests/main/quit-guard-strings.test.ts`,
`tests/main/linear-callback-page-strings.test.ts`,
`tests/main/about-panel-strings.test.ts`). Add one alongside any
further table.
This list is exhaustive — a main-process string that is not on it belongs behind
a locale-neutral code.

## Suppression

A literal that genuinely must not be translated — a brand name, a `⌘↵` glyph, a
shell command example — gets an `i18next-instrument-ignore` directive at the
call site. Never widen `lint.ignore` in `i18next.config.ts` to silence a real
string, and never delete a key to make `i18n:status` green.

## Backlog

There is none. `npm run i18n:status` reports **100% in both `ru` and `el`** as of
2026-09-01 — 2,557 keys across eight namespaces, with the migration's inherited
debt cleared by the audit in #250.

That makes the rule above absolute rather than aspirational: a change that leaves
an empty `ru` or `el` value is not "adding to a backlog", it is the *only* gap in
the catalogue. `el` reports a lower key total than `ru` — Greek has two plural
categories where Russian has four — which is expected, not a shortfall.
