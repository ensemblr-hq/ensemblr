# Ensemblr v0.1.17

Ensemblr 0.1.17 closes the last finding of the 2026-09-12 audit, wires per-turn diffs across the transcript footer and Changes panel, gives the app's own control-tool rows real bodies, tracks Claude Code background tasks on every surface that cares, and hardens the file search, composer, and sub-agent close paths.

### Highlights

* **The renderer no longer runs on `file:`.** SH-03 was the last open finding of the 2026-09-12 audit: a page on `file:` may read every file its user can, so a renderer XSS reached `~/.ssh/id_ed25519` with no IPC handler in the loop, and the CSP could not close it — the app needed `connect-src file:` to load its own assets. The bundle now serves from `app://bundle` over a scheme registered `standard` + `secure`, and `GrantFileProtocolExtraPrivileges` is off. The two are one change: a `file:` document with the fuse off has no usable origin, so every module script is refused and `localStorage` throws. The origin move is carried by 0.1.15's storage mirror, which had to ship first and did — anyone who has run 0.1.15 or 0.1.16 keeps their renderer state. An install that jumps straight from a pre-0.1.15 version has no mirror to seed from and comes up with renderer defaults: board order, viewed marks, pins, per-chat overrides. Nothing else; the rest is in SQLite. Incidentally: `img-src` admitted `linear-asset:` while the registered scheme is `ensemblr-linear-asset`, so every proxied Linear issue image was CSP-blocked in both serving modes — fixed in the same change. (#596)
* **Every turn now says what it did to the files.** A turn's footer carries the wall-clock time it ended and a chip per file it changed, with that file's line counts; clicking a chip opens that file at the turn's scope in the normal diff viewer. The Changes panel gains a "Latest turn" source resolved from the workspace's newest checkpoint. One `{ kind: 'turn', fromRef, toRef? }` scope routes all three surfaces through the plumbing that already exists; `fromRef` is the turn's pre-prompt checkpoint (ADR 0012). The transcript is not virtualized, so each turn's `git diff` is held back until its footer scrolls into view, and a frozen turn range never polls. Also fixes an existing latency bug the chips made visible: the checkpoint query neither polled nor was invalidated by the event stream, so a turn that had just finished showed no diff affordances until its tab remounted. (#592)
* **The app's own control tools now have real timeline rows.** Every `ensemblr_*` row but one used to unfold onto a raw JSON dump — a wait on delegated children, which is the row an orchestrating turn produces most of, rendered as one unwrapped line. Twelve ops now get shaped bodies (`wait_for_agents`, `read_conversation`, `get_last_message`, `get_conversation_status`, `list_models`, `recall_memory`, `list_workspaces`, `list_terminals`, `read_terminal_output`, `linear_list_issues`, `linear_get_issue`, `get_diff_comments`), plus `resolve_diff_comments` which shows the ids it could not close. Every settled control row carries a "Raw execution" disclosure that was previously gated behind extension-owned presentations, so a shaped body is a summary rather than a loss. Dispatch resolves by canonical name across the two runtimes rather than by the surface name they reach the timeline under. (#600)
* **Claude Code background tasks are visible across the app.** `Bash` launched with `run_in_background`, an `Agent` launched with `async_launched`, and the poll/stop verbs (`TaskOutput`/`BashOutput`, `TaskStop`/`KillShell`/`KillBash`) now read as distinct rows with their task id in the title; foreground `Bash` gains an outcome suffix. A blue sibling to the terminal-activity dot lights on the sidebar row and the dashboard card while any background task is live in the workspace, driven by the runtime's own `background_tasks_changed` level signal rather than paired against tool results (the SDK explicitly warns against pairing). A composer notice names what this chat left running, the quit confirmation counts background tasks alongside mid-turn chats, and the close-chat guard defers an idle tab that still holds tasks. Read-only mode now withholds the modern task verbs alongside the legacy aliases, so a mode that blocks `Bash` cannot be steered around by polling or stopping an earlier session's still-live shell. (#604)
* **A ready-to-merge PR with unpushed commits reads as such.** A ready verdict is GitHub's reading of the published tip; on a branch carrying work it has not seen it does not describe what merging would take. The sidebar row and the board card now report that as `pr-unpushed` — the up-arrow the header's Push action already uses, in the warning tone — rather than the green ready arrow. The cached PR snapshot's branch sync reaches the renderer, so a row reports unpushed commits with no extra git query, and the open workspace's row adds uncommitted edits from the working-tree status the route layout already reads. (#601)
* **A sub-agent's tab holds itself open while its delegate is running.** Closing a spawned child's tab mid-run used to stop the agent its orchestrator was still waiting on. The refusal now lands in `resolveRunningCloseTarget`, which the tab strip and the ⌘W handler already share, and takes the union of the live composer flag and the persisted snapshot so ⌘W is never weaker than the affordance. A finished delegate whose orchestrator never cleaned up still closes straight through, and a streaming root chat still raises the usual confirmation. (#599)
* **The Linear picker's chip lands immediately, comments fill in behind it.** Picking a Linear issue from the composer's "Link issue" picker used to dismiss the dialog and show nothing for about five seconds — one blocking GraphQL round-trip on every first pick, because list sync's `upsertIssues` never wrote `commentsSyncedAt` so the main-process cache staleness gate never passed. `attachLinearIssue` now runs in two passes: the chip lands from the row the picker already holds, the comments are fetched behind it, and the chip is repointed at the fuller document. GitHub issues arrive whole from `gh` and take the first pass only. (#598)
* **The file search dialog no longer stutters as you type.** The dialog used to render every previewable workspace file — up to the 5,000-entry ceiling — and leave filtering to cmdk, which reorders items by walking them through the DOM on every keystroke, opens a filtered set mid-list, and could leave Enter inert when the row holding cmdk's selection unmounted mid-keystroke. Ranking now happens here behind `shouldFilter={false}` with the existing fuzzy scorer, debounced at 80ms, list rewound on a settled query, and the selection held explicitly. Full ranking pass: 3-6.5ms, down from 25-87ms — the character-by-character fold was 63% of it, and pure ASCII now takes a native whole-string `toLowerCase` while non-ASCII keeps the walk to preserve contextual rules. (#597)
* **The "Raw execution" disclosure stays inside its own tool row.** `MessageResponse` put `size-full` on the Streamdown root, so a flex-item chain measured markdown plus `mt-3` plus the details for the parent's height, then let the markdown's `height: 100%` expand to it and push the details past the parent's bottom edge. Latent until #600 gave every control row a raw-execution disclosure; the same swallow hit `ChatMessageText`, which renders two sibling answers while a turn streams. Sized by width only now. (#602)

### Install

macOS:

```sh
brew install --cask ensemblr-hq/tap/ensemblr
```

Linux:

```sh
curl -fsSL https://www.ensemblr.dev/install.sh | sh
```

The `.dmg` is signed with a Developer ID certificate, hardened-runtime, notarized by Apple and stapled, so it opens without a Gatekeeper prompt and validates offline. The Linux installer needs no root, writes nothing outside `$HOME`, verifies the download against the digest GitHub publishes, and keeps a manifest so `--uninstall` removes exactly what it added. Re-running it is an update.
